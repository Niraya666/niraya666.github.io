值得关注的研究和论文#

AutoMem: Automated Learning of Memory as a Cognitive Skill#

arXiv:2607.01224

把 Memory Management 视为可独立学习的认知技能，让 Agent 学会判断什么信息值得写入、何时检索，以及如何避免重复、过期和无用记忆污染上下文

核心思路

  • 把 read、write、search、append、create 等文件系统操作提升为与环境动作同等地位的 Action
  • 同时优化两个层面：Memory Scaffold 指 Prompt、代码、文件 Schema、Action Vocabulary 和校验逻辑等支撑记忆行为的结构；Memory Proficiency 指模型选择合适记忆动作的能力
  • 让 Meta-LLM 读取完整 Episode Trace、Memory Directory 和 Agent Code，像 Code Reviewer 一样诊断失败模式并自动修改 Scaffold
  • 将记忆训练与任务行动模型分离：第二个 Outer Loop 只训练负责记忆操作的 LoRA Memory Specialist，执行游戏动作的 Base Model 保持冻结

具体实现

  • Inner Loop：文件系统记忆 Agent。Agent 在每个 Episode 中拥有一个磁盘目录作为外部记忆；每一步包含两个 Routine：LOG 判断刚刚发生的事情是否值得记录以及写到哪里，PLAN 判断行动前需要检索哪些记忆，再选择下一步环境动作
  • Outer Loop #1：自动优化 Memory Scaffold。Meta-LLM 读取完整 Episode Trace、当前 Memory Files 和 Agent Code，诊断 Scaffold 中导致失败的部分，再修改代码、Prompt、文件结构或 Action Vocabulary
  • Outer Loop #2：训练 Memory Specialist。Scaffold 收敛后，Base Model 在最终结构下运行大量 Episode；Meta-LLM 从轨迹中筛选值得强化的记忆操作样本，并联合选择 LoRA 配置

实验结果

在 Crafter、MiniHack 和 NetHack 三个程序生成的长程游戏中，仅优化记忆能力、保持任务行动行为不变，就使 Base Agent 的表现提升约 2～4 倍，并让 32B 开源模型达到可与前沿闭源系统竞争的水平

The Verification Horizon: No Silver Bullet for Coding Agent Rewards#

arXiv:2606.26300

分析 Coding Agent 训练中 Reward / Verifier 设计为何越来越困难，并提出按任务形态构建验证系统的框架

过去常说“验证比生成容易”，但对今天的 Coding Agent 来说这一关系正在反转：模型越来越擅长生成复杂候选解，真正困难的是如何可靠判断结果是否满足用户意图

作者认为任何 Verifier 都只是人类意图的 Proxy；一旦被用于训练优化，Proxy 与真实意图之间的缝隙就会被放大，最终表现为 Reward Hacking 或信号饱和

验证信号的三个维度

  • Scalability：验证成本能否随任务规模和训练规模扩展
  • Faithfulness：验证信号是否真实反映用户意图，而不是可被钻空子的表面指标
  • Robustness：当策略模型持续变强时，验证器是否仍能稳定区分高低质量输出

四类任务中的验证难题

  • SWE-like 代码修复：测试用例容易成为不完整的意图代理，需要结合任务质量 Judge 与轨迹行为 Monitor
  • 前端开发：仅靠静态截图或规则难以覆盖交互体验，需要从 Static Judge 转向 Interactive Judge
  • 真实用户 Agent 任务：用户反馈稀疏且通常只指向局部问题，需要转化为 Span-level 训练信号
  • 长程代码生成 / 从零构建 Repo：验证成本与生成成本同步增长，需要自动化 Agent Verifier，并持续更新验证策略

论文的核心结论是：不存在能够长期固定不变的 Reward Function，验证系统必须与生成模型共同演化

Rethinking the Evaluation of Harness Evolution for Agents#

arXiv:2607.12227

重新审视自动 Harness Evolution 方法的评估是否公平、可信：性能提升究竟来自可复用的 Harness 设计，还是更多推理预算、搜索和对 Benchmark 的记忆

现有评估协议的问题

  1. 在公开 benchmark 任务上运行 Agent；
  2. 查看轨迹、单元测试结果和失败原因；
  3. 多轮修改 Harness；
  4. 最后仍在同一批 benchmark 任务上报告性能。
  • 缺少公平基线：Harness Evolution 没有在相同推理预算与反馈条件下，与 Parallel Sampling、Sequential Refinement 等简单 Test-time Scaling 方法比较
  • 搜索集与测试集重合：同一批 Benchmark 同时用于 Harness 搜索和最终报告，容易产生过拟合

论文的主要贡献是提出更严格的评估框架，而不是新的 Harness 算法。该框架统一控制每种方法能够看到的反馈、额外计算的用途、被修改的对象，以及最终产物是否能跨任务复用

方法 固定/修改对象 额外计算用途
Parallel Sampling 固定 Harness 独立生成多个解，扩展搜索宽度
Sequential Refinement 固定 Harness 根据上一次轨迹逐步修改解，扩展搜索深度
Harness Evolution 修改共享 Harness 根据一批任务的经验更新通用 Harness
Harness Scaling 修改任务专属 Harness 针对单个任务逐轮修改 Harness

Harness Scaling 诊断基线

Harness Scaling 不在一批任务上学习通用 Harness，而是针对当前单个任务重复执行：运行 → 分析失败 → 修改 Harness → 再次运行。它相当于 Harness 层面的 Test-time Scaling，可用于区分：

  • Harness Evolution：试图发现可跨任务复用的设计原则
  • Harness Scaling：针对当前任务进行临时适配和记忆

作者进一步分离 Harness 搜索任务与最终测试任务。Terminal-Bench 2.1 上的实验显示，在匹配反馈和推理预算后，自动 Harness Evolution 并不能稳定超过简单 Test-time Scaling，且在 Held-out Tasks 上的泛化能力有限

From Memory to Skills: Evidence-Grounded Co-Evolution Governance for Long-Horizon LLM Agents#

arXiv:2607.16621

提出无需训练的 MSCE（Memory–Skill Co-Evolution）框架，将长程 Agent 的噪声交互轨迹逐步转化为有证据支持、可验证、可维护且可安全调用的技能

三级记忆：分离证据、程序和环境认知

层级 保存内容 主要作用
L1 Trace Memory 状态、动作、观察、反思和步骤价值 保存可审计的原始证据
L2 Policy Memory 触发条件、操作步骤、验证规则、适用边界 归纳跨任务可复用的程序
L3 Environmental Cognition 环境结构、行为规律、约束条件 理解环境“是什么样的”

从策略晋升为技能

MSCE 不直接从单条轨迹生成技能，而是先从多个 Episode 的证据中归纳 L2 Policy，再判断该策略是否满足晋升条件。一个 L2 Policy 只有在以下条件成立时才能变成技能：

  • 存在可追溯的 L1 支持证据
  • 估计收益为正
  • 最近证据与当前触发条件、流程和适用边界保持一致
  • 技能中的工具和命令确实出现在支持轨迹中
  • 通过确定性的结构与证据验证

Reflection-weighted Value Backfilling

长程任务通常只有最终成功或失败奖励，很难判断中间哪些步骤真正重要。MSCE 同时利用：

  • 稀疏但相对可靠的最终反馈
  • 密集但可能不可靠的步骤反思

对于终止步骤，价值直接等于整个 Episode 的最终奖励 $R_i$；对于更早的步骤，采用：

$$ V_t = \alpha_t R_i + (1-\alpha_t)\gamma V_{t+1} $$

其中：

  • $V_t$：当前步骤的价值
  • $R_i$：整个 Episode 的最终反馈
  • $\gamma$：时间折扣，实验中为 0.9
  • $\alpha_t$：该步骤反思的可信度和信息量

技能生命周期

  • Probationary：新生成但尚未充分验证
  • Active：可靠度达到阈值，可默认检索
  • Archived：长期不用、可靠度过低或反复失败，不再默认调用

MSCE 在 EvoAgentBench 和 LoCoMo 上优于多种 Skill-augmented 与 Memory-driven Agent 基线，并展现出跨领域迁移和持续演化能力

突然意识到，人生的奥德赛时期，好像就是一场盛大的FOMO#

奥德修斯的漂泊，从来不是主动选择。他得罪了波塞冬，被惩罚不得归家。

我们没人惩罚，没人流放。我们主动解开缆绳，主动驶离每一个可以靠岸的港口。不是因为我们不想回家，而是因为我们害怕——害怕此刻靠岸的那个“家”，不是所有可能性里最好的那个。所以我们漂泊，不是被神驱逐，而是被恐惧驱赶。

于是我们拼命追逐每一艘经过的船，害怕错过任何一个可能通往“正确人生”的航向。这场名为“寻找自我”的奥德赛，最终变成了一场害怕错过一切的FOMO（Fear of Missing Out）。

而现实一旦展开，就会显露局限、乏味、代价。你害怕的不是选错，你害怕的是选完之后必须要面对的那种“就这？”——是你翻开底牌后发现，它不如握在手里时那么光芒万丈。

奥德赛时期的终结，不始于“找到正确的港口”，而始于你承认一个简单的事实：你无法拥有所有可能性，而且你从来就没有拥有过…终结的第一步，是亲手关掉一些门。不是“被关掉”，是主动关掉。

How To Build A Company With AI From The Ground Up#

The right person with AI tools can now build features that used to require an entire team or were just impossible

In the old model, companies essentially operated as open-loop systems. A decision would be made and executed, but its outcome would not necessarily be measured systematically or used to adjust the process. A closed-loop system, by contrast, continuously monitors its output and changes its process so that it can better achieve the stated objective.

Every important company process should be enclosed within an intelligent closed loop: the loop captures information, feeds that information back into an intelligent system, and improves the process over time.

To construct these closed loops, the entire company must be made queryable—in other words, the organization must be understandable to AI. Every significant action should leave behind an artifact from which the intelligence at the center of the company can learn and improve itself.

The individual contributor is essentially a builder-operator—someone who directly makes things and operates them. In an AI-native company, this category is not confined to engineering; people in operations, support, and sales build as well.

The DRI concentrates on strategy and customer outcomes. This person is not a conventional manager, but the individual who bears unambiguous responsibility for a particular result: one person, one outcome, and nowhere to hide.

The AI-founder type continues to build, coaches others, and leads through personal example. Founders should be at the front, demonstrating the scale of the new capabilities rather than delegating AI strategy to someone else.

The crucial shift will be to maximize token usage rather than headcount. Companies that adopt this structure can produce disproportionate results with substantially smaller teams. A single person equipped with AI tools may perform work that previously demanded a large engineering team in a pre-AI company.

Early-stage founders possess a significant advantage because they do not have legacy systems, entrenched organizational charts, or thousands of employees who must be retrained. Existing companies must continue maintaining and growing a live product while simultaneously undoing years of standard operating procedures and foundational assumptions about software development.

从Databricks Summit聊聊，AI时代数据平台应该如何建设？#

AI 这一轮，算法、算力、数据这三样里，数据是被定价得最慢的那一个。

模型在趋同，算力能用钱买到，到头来真正还算得上护城河的，只剩数据。这句话，我越想越认同。

数据库正在从"存储和查询"，慢慢长成"事实、状态、语义、治理和行动"的统一底座。

也是我感受最深的：它产品的默认用户，还是人，不是 agent

过去数据库回答的是"这条 SQL 怎么跑得更快"；以后它要回答的是"一个 agent 在做决策时，怎么拿到最新、最可信、最便宜、可审计的上下文"。

优绩主义者迟早要经历奥德赛时期#

我们将整个现代资本主义建立在竞争之上。这是一个文明的错误。…人类的欲望并非自发，而是模仿性的…竞争并非价值的标志。它只是表明大家都盯着同一个点，而没人再创造任何东西。

我们正步入一个丰裕的世界。人工智能和机器人技术将大幅降低几乎所有产品的生产成本。在这样一个世界里，为现有市场而战变得完全荒谬。零和游戏失去意义，因为将有数量级的新价值空间出现。唯一真正有趣的游戏，将是创造。不是争夺，而是创造。未来的人类只有一个真正高贵的角色：创造真正的价值。而创造意味着摆脱模仿。不做大家都在做的事，而是让不存在的东西浮现。

能力 + 努力 = 成功，这本是合理的公式，可在当下的教育环境中，却被异化成了：智商 + 高强度自我逼迫，就能换来人人羡慕的人生。

优绩主义更像是一份与魔鬼的契约：人们割舍真实的自我，把自己塑造成功利化的工具，以此换取世俗定义的成功。

“工具化自我” 也逐渐变得泛滥。这时人们才发觉，当初被丢掉的真实自我，才最珍贵。
