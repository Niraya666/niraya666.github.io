值得关注的研究和论文#

Not All LLM Reasoning is Visible in the Chain-of-Thought#

arXiv:2607.22925

大模型的一部分有效计算并不会以可读的 Chain-of-Thought 呈现。即使模型输出的只是固定、无语义的 filler tokens，它们对应的隐藏状态仍可以成为内部计算空间，提高任务准确率，甚至帮助模型完成输出中完全不可见的附加目标

Invisible Reasoning

论文将“对最终行为或答案产生实际影响，但没有在输出 token 中留下可解释痕迹的内部计算”定义为 Invisible Reasoning（不可见推理）。

诊断方法

  • 在问题和答案之间插入对所有问题都完全相同的 filler token 序列；如果加入后准确率提高，说明有用信息在其隐藏状态中逐渐形成，而非写在 token 表面
  • 性能增益依赖 filler token 的具体类型，且不同模型偏好不同的 filler token，说明这一现象与模型自身的表示空间和 attention pattern 有关
  • 结合 token 顺序调换、activation patching、residual stream 线性探针与 attention masking，判断有用信息在哪些层形成，以及计算是否分布在整段 filler span 中

安全实验

模型表面任务是完成四位数乘法，但系统提示要求它在答案满足某些模运算条件时输出 N/A。要正确执行，模型必须在输出答案前先计算乘积、检查隐藏条件，再决定输出数字还是 N/A，而这一过程不会出现在可见 CoT 中。

RL 的影响

实验中，经过 RL 训练的模型在测试时不再从 filler tokens 中获得额外收益。这说明 filler token 带来的隐藏计算能力不一定会在后训练中持续保留，但也进一步证明：仅观察可见 CoT 不足以完整审计模型的计算过程。

DataSpace: Benchmarking Data Agents for Verifiable Analytics over Heterogeneous Workspaces#

arXiv:2608.03451

KDD Cup 2026 Data Agents for Complex Data Analysis 的官方评测 benchmark，考察 Agent 能否在杂乱的数据工作区中自主找到正确证据，完成跨文件、数据库、文档与视频的数据对齐和计算，最终输出可以确定性验证的完整结果表

三个 benchmark 缺口

  • Workspace scope：不再预先指出正确数据源，而是给 Agent 一个完整的异构 workspace
  • Output contract：所有任务统一要求输出完整结果表，而不是单句答案或自由形式分析报告
  • Evaluation semantics：结果由程序确定性验证，不依赖另一个 LLM 充当 judge，同时允许列名、格式等语义等价变化

DataSpace-Builder：从 Text-to-SQL “编译”出异构 Agent 任务

DataSpace-Builder 从 EHRSQL 和 BULL 中的 Question + Database + Gold SQL 出发，将其转换为 Question + CSV/JSON/SQLite/PDF/Markdown/Video → Complete Table。

  1. Cross-Language Transformation：联合迁移 Question、Database 和 SQL，对 table name、column name、cell value、SQL literal 及问题中的对应概念建立统一 replacement map；完成后再检查查询等价性与 Question-SQL 语义一致性
  2. Constraint-Aware Relational Sampling：从 Gold SQL AST 中提取 primary/foreign keys、join columns、filter values、boundary values 和 target entities 作为 safeguard constraints，先保护关键行，再沿 relational key 做 closure 并采样其他行
  3. Multimodal Rendering：将 relational tables 重新渲染为 CSV、JSON、SQLite、Markdown、PDF 和 Video 等异构 artifact
  4. Human Review & Repair：每个任务由 11 人领域专家池中的两人独立盲审，先在不看 gold 的情况下解题，再共同检查 gold、数据充分性、问题明确性、数值精度、行序和数据类型；无法修复的任务直接删除

确定性语义评估

严格 string match 对格式差异过于敏感，LLM Judge 则有随机性，还可能把不完整答案判为正确。DataSpace 因此设计了 semantics-aware deterministic evaluator，在保证内容完整的前提下，允许规定精度范围内的数值差异和语义等价的格式变化。

From LLM Inference to Agentic Workloads: Characterization and Implications for Serving Systems#

arXiv:2608.15127

当 AI 从一次 Request → LLM inference → Response 变成持续几十分钟甚至几小时、不断调用工具的 Agent 之后，现有围绕 GPU utilization、batching、KV Cache、prefill/decode 和 tokens/s 构建的 LLM serving infrastructure 已无法完整描述真实系统瓶颈

AgentSysBench

论文提出 benchmark 与 measurement framework AgentSysBench，覆盖 10 类代表性 Agent 应用：

类型 Agent
RAG RAG
AI Search DeepResearch
Multimodal HuggingGPT
Coding Mini-SWE
Terminal Codex
Browser WebAgent
GUI GUIAgent
Tool-rich Assistant Claude Code
Office Agent Openclaw
AutoResearch Pi-AutoR

作者将 Agent workload 表示为：

$$W=\langle R,T,M,O\rangle$$

其中 $R$ 为 request distribution，$T$ 为 tools/environment，$M$ 为 models，$O$ 为 orchestration。Serving System 表示为：

$$S=\langle H,C,A\rangle$$

其中 $H$ 为 hardware，$C$ 为 component serving mechanism，$A$ 为 deployment architecture。最终观察到的系统行为为：

$$Y=\Phi(W,S)$$

即 Agent 性能是 workload 与 serving system 共同作用的结果。

主要发现

  • Shifting Bottleneck：LLM 并不一定是 Agent 的瓶颈，不同任务阶段会在模型推理、工具、网络、存储和 orchestration 之间转移
  • Token Consumption Snowball：工具输出与历史状态不断回填上下文，使 token 消耗随任务进程滚雪球式增长
  • Large State Machine：Agent 是由模型调用、工具执行、环境变化和重试构成的巨大状态机，不能再被当作单个 inference request
  • Control-Plane Tax：大量 token 用于维护 Agent 的计划、状态、工具协议和错误恢复，而不是直接生成最终答案
  • Tool Cache：Agent infrastructure 不仅应 cache LLM prefix，还可以缓存 Search、URL、Retrieval、Tool output 和 Environment object

Agent 能干活以后，人反而更需要会管理#

我们不该退回到逐行审查代码、逐个批准命令的微观管理中，因为那种做法会彻底抵消代理带来的效率红利

我们应当从过去的过程陪跑转向结果治理，重新定义完成标准、要求提供轻量凭证、按风险进行抽检，并建立起异常自动升级的通道

为了避免让收据变成阻碍效率的繁琐形式主义，引入风险分级是非常必要的

不同的任务需要的证明程度完全不同，而评估管理力度的基本单位应该是具体的任务，而不是代理本身。

AI 不自动带来超级组织#

十年前，企业不敢公开说自己要用机器替代人，那听起来冷酷、反社会、缺乏人味。今天，企业开始把这件事包装成远见。裁员不再只是削成本，它被讲成通往未来组织形态的一张船票。

AI 裁员的真实含义，未必是“机器已经替代人”。它更像一种新管理语言：当企业想削掉中层、压缩白领、重写组织结构时，AI 给了它一个听起来面向未来的理由。

于是，一个非常顺理成章的故事出现了。个人会被 AI 增强，成为“超级个体”。企业也会被 AI 增强，成为“超级组织”

这就是“超级组织”叙事最尴尬的地方。它想同时拥有两个结论：一边说 AI 会让个体前所未有地强大，一边说大企业会在这场个体增强中变得更庞大、更稳固、更不可替代

裁员时代有一个常见幻觉：企业裁掉的是冗余的人手。 这个说法在流水线时代比较容易成立。机器替代的是重复动作，企业减少的是可替换岗位

当这些人离开组织，他们带走的不只是技能简历。他们还带走了组织的隐性地图

AI 把这段距离压短了。一个被裁掉的中层经理，未必能立刻做出一家亚马逊，但只要他熟悉某个垂直环节，就能做出一个更薄、更快、更便宜的工具

大公司的威胁不再只来自另一家大公司，它可能来自一万个非常小、非常窄、非常懂局部需求的一人公司。

员工和创业者之间的边界正在变薄。当一个人能做十个人的活，他到底是一名员工，还是一家暂时寄居在公司里的微型企业？企业越强调 AI 提效，这个问题越难回避。

这套结构的价值，来自一个基本事实：人类协作很贵。

这就是 AI 对企业的第一刀，它瓦解的是公司作为一种组织形式存在的理由。

正是大企业不愿自己处理、却又离不开的大量流程。可 AI 正在拆它

AI 时代如果让更多小单元具备独立交付能力，风险不一定消失，但风险可以从组织内部转移到资本组合中。

更现实的路径，可能是大公司自己把内部拆成大量更小的经营单元。

未来的小公司、一人公司、智能体网络，也许会通过类似 Git、API、A2A 的方式协作。大家围绕标准接口交付任务，围绕协议交换数据，围绕平台建立声誉，围绕合约和支付系统完成结算。

“超级组织”这个词的诱惑在于，它过于顺滑的将 AI 赋能个人过渡到了 AI 赋能企业。 真正退潮的，是公司作为“大量人力 + 中层管理 + 内部协调”的历史功能。

从 Agent Flow 到 AI Native：为什么通用 Agent 是“饮鸩止渴”#

用户为什么要选择某个 Agent？ 原因只有两个。 第一，只有你能解决某些问题。 第二，你真的能解决问题

过去 20 年所有的基建都是为“人类”设计的，不是 LLM friendly 的，自然处处都是别扭。

只要信息给够，大模型就能很好地接住。但如果是需要反复和人确认的任务，或者是一个局部但很深、需要大量交互和判断的任务，我和我的 Sub-agent 都会极其痛苦。当前的组织架构和任务流，对 LLM 是极度不友好的。

层级再怎么包装成扁平，只要任务、权限、上下文和反馈的链路很长，它就还是厚的。 真正的扁平，不是物理空间上离得近，而是组织的链路足够短

在乌兰察布，89个数据中心跟羊抢水喝#

所有人都知道AI耗水，但颠覆很多人认知的是，AI数据中心选址，几乎清一色往极度缺水的干旱地带扎。

所以一旦未来发生严重旱情，牧民的问题会非常直接：为什么外来的数据中心能获得稳定供水，而本地人却要被逼着节水关井？

法律把优先级写得明明白白。但在实际操作中，一个GW级数据中心带来的投资和税收，远比几千户牧民的羊群有分量。

中国式 FDE 注定失败#

很多所谓 AI 转型，并不是因为企业需要 AI 转型，而是让企业先接受“我们必须做 AI”这个结论，才开始寻找业务场景

哪怕在 FDE 实施的过程中，真找到了 AI 可以介入的场景，也不一定真的需要用 AI 来做。

但是当一个项目一开始就被定义为 AI 转型，FDE 进入现场以后就不是判断客户的问题该怎么解决，而是在证明如何用 AI 解决客户的问题。

真正的 FDE，应该回答企业到底存在什么问题，而不应该反问企业哪里可以用 AI。

为什么超级个体不需要超级团队？#

本文想给出的判断是，超级个体是一个真概念，但超级团队是一个伪概念

超级团队”这个词的全部说服力，建立在一个未经检验的算式上，也就是能力可以相加。但这个算式在组织学里已经被反复批驳。

实际生产力 = 潜在生产力 - 过程损失

向进度落后的软件项目中增加人力，只会让它更落后。

团队的产出随人数线性增长，但沟通路径随人数的平方增长。n 个人之间的沟通路径是 n(n-1)/2 条。

当团队规模越过某个临界点，新增的每一个人所带来的沟通负担，都会超过他所带来的产能

团队规模不应超过两个披萨可以喂饱的的人数，通常少于 10 人），这是一条关于平方曲线的工程纪律。

而一个超级个体的全部价值，恰恰在于他有大量自主判断、有完整的品味体系、有对“什么是对的”的独立感知。

一个百人部门能够运转，是因为公司花了大量制度成本，把绝大多数人的判断权收拢到了少数人手里，剩下的人交付执行。层级制的真实功能不是管理人，是收缴判断权。

因为在市场上一次次谈判太贵，把交易搬进企业内部更便宜。公司用一份雇佣合同，把未来无数次“我同意”一次性买断，而不必每次都说服。

超级个体的核心资产，恰恰是不可让渡的判断，尤其是核心判断。 他稀缺是因为他知道什么值得做，什么做法是对的，什么细节不能妥协

它们只提供三样东西：无限的执行力，零摩擦的对齐，随时待命的注意力。这三样，是“超级团队”都给不了的。

现在对照一下，超级个体真正缺的是什么？第一，他不缺判断，但他缺执行带宽。一个想法从成型，到落地，中间有九成是重复劳动。这部分需要产能，而非更多的智慧。第二，他不缺方向，他缺零摩擦的对齐。他和自己是天然对齐的，这是他效率的全部来源。任何引入外部判断的动作，都在破坏这个优势。第三，他不缺勇气，他缺承担代价的能力上限。他愿意为结果负责，只是一个人能承担的后果有限。

因为工具越公开，剩下的那部分差距，就越取决于不可让渡的东西。 它也是奥德修斯的那把弓。摆在所有人面前，谁都可以试，而拉开的人依然是少数。
